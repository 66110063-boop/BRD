# ระบบตรวจสภาพรถยนต์ (Vehicle Inspection System - VIS)
> ระบบลงทะเบียนและติดตามผลการตรวจสภาพรถยนต์ ตรอ. ยุคใหม่ ตามข้อกำหนด Business Requirements Document (BRD)
> ออกแบบตามหลักปรัชญา **Hallmark Anti-AI-Slop Design Guidelines (v1.1.0)** เพื่อประสิทธิภาพสูงสุดหน้างานจริง

---

## 📋 ภาพรวมโครงการ (Project Overview)
โครงการนี้เป็นการปรับโฉมและยกระดับระบบตรวจสภาพรถยนต์เดิม (**ReMo V 3.62.1 Thai**) ให้กลายเป็น Modern Web Application ที่มุ่งเน้น **Input Speed, Visual Hierarchy และ Precision** โดยรองรับผู้ใช้งาน 3 บทบาทหลัก:
1. **เจ้าหน้าที่หน้าเคาน์เตอร์ (Receptionist):** ลงทะเบียนรถ ตรวจสอบประเภท รวดเร็วผ่านคีย์ลัดและบาร์โค้ดสแกนเนอร์ พิมพ์บัตรคิวตรวจ
2. **ช่างตรวจสภาพประจำเลน (Lane Inspector):** ติดตามสถานะคิว ผลตรวจ 6 รายการหลักจาก 9 อุปกรณ์ฮาร์ดแวร์แบบ Real-time
3. **หัวหน้างาน / ผู้ตรวจสอบ (Supervisor):** ควบคุมสิทธิ์การแก้ไขข้อมูล ปลดล็อกข้อมูลที่ตรวจแล้วด้วย PIN และระบุ Audit Reason ตาม BRD ข้อ 4.2

## ⚡ จุดเด่นและฟีเจอร์หลัก (Key Features)

### 1. การทำงานที่เน้นความเร็วคีย์บอร์ด (Keyboard-First & Scanner Ready)
- **Autofocus อัตโนมัติ:** เมื่อเปิดหน้าเว็บ เคอร์เซอร์จะกระพริบรอที่ช่องเลขทะเบียนทันที
- **คีย์ลัดหน้างาน:**
  - `[F4]`: ล้างฟอร์มทั้งหมด พร้อมดึงเคอร์เซอร์กลับมาที่ช่องทะเบียนทันที
  - `[F9]`: บันทึกข้อมูล ส่งต่อไปยังช่องตรวจ และเปิดบัตรคิวพิมพ์ทันที
- **USB Barcode / QR Scanner:** รองรับสแกนเนอร์ USB HID (ส่งค่าตามด้วย Enter)
  - ยิงที่ช่องทะเบียน: ตรวจสอบและบันทึกส่งเข้าช่องตรวจทันที
  - ยิงที่ช่องค้นหาคิว: ค้นหาและเปิดหน้าต่างผลตรวจ 6 รายการทันที

### 2. โครงสร้างหน้าจอ 7 : 5 Workbench
- **ฝั่งซ้าย (7 คอลัมน์):** ฟอร์มลงทะเบียนรถ แบ่งสัดส่วนชัดเจน
  - ข้อมูลหมวดทะเบียนและประเภทรถ (รย.1, รย.2, รย.3, รถโดยสาร, รถบรรทุก)
  - ข้อมูลตัวถัง ยี่ห้อ รุ่น และเลขคัสซี (VIN)
  - สเปกทางเทคนิค: ปุ่ม Segmented Button เลือกเชื้อเพลิง (เบนซิน, ดีเซล, ก๊าซ, EV, ไฮบริด) และเพลาล้อ (2, 3, 4 เพลา พร้อมระบุเพลาเบรกมือ 🅿️)
- **ฝั่งขวา (5 คอลัมน์):** หน้าจอคิวตรวจและผลเรียลไทม์ (Lane Monitor)
  - กรองสถานะได้: ทั้งหมด, กำลังตรวจ (`testing`), ตรวจผ่าน (`passed`), ตกเกณฑ์ (`failed`)
  - ตรวจสอบค่านำเข้าจากเครื่องมือตรวจสภาพ 6 จุดหลัก (ความเร็ว, เสียง, ควันดำ/CO/HC, ศูนย์ล้อ, ห้ามล้อ, โคมไฟหน้า)

### 3. ระบบควบคุมสิทธิ์การแก้ไข (BRD Section 4 Compliance)
- **รถสถานะ "รอตรวจ" (Waiting):** มีปุ่ม `[✏️ แก้ไข (Auto)]` ดึงข้อมูลกลับมาแก้บนฟอร์มได้อิสระทันที
- **รถสถานะ "ตรวจแล้ว" (Testing / Passed / Failed):** ระบบล็อกข้อมูลอัตโนมัติ แสดงปุ่ม `[🔒 ล็อก ขอแก้]` ซึ่งต้องให้หัวหน้างานใส่รหัส **Supervisor PIN** พร้อมเลือกเหตุผลประกอบการขอแก้ไข

### 4. ตรวจสอบสถานะการเชื่อมต่อฮาร์ดแวร์ 9 อุปกรณ์
แถบ Header ตรวจสอบสถานะอุปกรณ์ทดสอบทั้ง 9 รายการ พร้อมระบบแจ้งเตือนกรณีสายหลุด (เช่น `ควันดำ (COM3 หลุด) ⚠️` สีส้มกะพริบ) และสามารถคลิกสลับสถานะ Online/Offline เพื่อจำลองการสาธิตได้

### 5. โครงสร้างข้อมูลพร้อมเชื่อมต่อ Backend (BRD Section 6 Schema)
ฟังก์ชัน `saveRegistration()` ส่งออก JSON Payload ที่แมปตรงกับตาราง `vehicle_registration_transactions` 1:1 พร้อมเชื่อมต่อ REST API หรือ WebSocket ได้ทันที

## 🎨 มาตรฐานการออกแบบ (Hallmark Anti-AI-Slop)
- **Typography (2+1 Rule):**
  - Headings / Display: `Prompt`
  - Body & Form: `Sarabun`
  - Numeric & Measured Data: `JetBrains Mono` พร้อม `tabular-nums`
- **Color System:** OKLCH Palette (Anchor Hue 250 - Tech Cobalt)
- **No AI Slop:** ปราศจาก Gradient สีม่วง-ฟ้า, ปราศจาก Card ซ้อน Card, ขอบตัดด้วย Hairline Divider ชัดเจน สไตล์ Industrial Terminal

## 🚀 วิธีการเปิดใช้งาน (Getting Started)
ไฟล์ทั้งหมดถูกออกแบบให้เป็นแบบ **Zero-Build & Self-Contained**:
1. Clone หรือดาวน์โหลด Repository
2. ดับเบิลคลิกเปิดไฟล์ `index.html` บนเว็บเบราว์เซอร์ (Google Chrome, Microsoft Edge, Safari) ได้ทันทีโดยไม่ต้องติดตั้ง Node.js หรือ Web Server
